FSPEC & UAP

User Application Profile (UAP) Kullanıcı Uygulama Profili (UAP)

29 Positions — 5 Blocks 29 Pozisyon — 5 Blok

What is the UAP? UAP Nedir?

The User Application Profile (UAP) defines the order in which data items appear in a CAT011 record. Each CAT011 message starts with an FSPEC (Field Specification) — a variable-length bitmask that indicates which data items are present in the record. Kullanıcı Uygulama Profili (UAP), veri öğelerinin bir CAT011 kaydında görülme sırasını tanımlar. Her CAT011 mesajı, kayıtta hangi veri öğelerinin bulunduğunu gösteren değişken uzunluklu bir bit maskesi olan FSPEC (Alan Belirtimi) ile başlar.

How FSPEC works: Each bit in the FSPEC corresponds to a data item position in the UAP. If the bit is 1, the corresponding data item is present. If 0, it is absent. The last bit (bit 1) of each FSPEC byte is the FX (Field Extension) bit — if set to 1, another FSPEC byte follows. FSPEC nasıl çalışır: FSPEC'teki her bit, UAP'taki bir veri öğesi pozisyonuna karşılık gelir. Bit 1 ise ilgili veri öğesi mevcuttur. 0 ise yoktur. Her FSPEC baytının son biti (bit 1), FX (Alan Genişletme) bitidir — 1 olarak ayarlanmışsa, başka bir FSPEC baytı gelir.

Data Item Format Types Veri Öğesi Format Tipleri

Format Format Description Açıklama Example Örnek
Fixed Always the same number of bytes. The number in parentheses is the byte count. Her zaman aynı sayıda bayt. Parantez içindeki sayı bayt sayısıdır. I011/000 — Fixed (1)
Variable Starts with a minimum number of bytes; extends via FX bits. Each byte's bit-1 is FX: if 1, another byte follows. Minimum sayıda baytla başlar; FX bitleri ile genişler. Her baytın bit-1'i FX'tir: 1 ise başka bir bayt gelir. I011/170 — Variable (1+)
Compound Has its own internal FSPEC-like primary subfield indicating which sub-items are present, followed by the sub-item data. Hangi alt öğelerin mevcut olduğunu gösteren FSPEC benzeri kendi dahili birincil alt alanına sahiptir, ardından alt öğe verileri gelir. I011/380, I011/390
Repetitive Starts with a 1-byte repetition factor (REP), followed by that many fixed-size records. 1 baytlık tekrar faktörü (REP) ile başlar, ardından o kadar sabit boyutlu kayıt gelir. I011/605, I011/610
Explicit Starts with a 1-byte length indicator, followed by that many bytes of data. Content is implementation-defined. 1 baytlık uzunluk göstergesi ile başlar, ardından o kadar bayt veri gelir. İçerik uygulamaya özel tanımlanır. I011/SP, I011/RE

Important Notes Önemli Notlar

Tip: Not all 5 FSPEC bytes are always present. If a message only uses data items from Block 1, only 1 FSPEC byte is needed (with FX=0). The FX chain extends only as far as necessary. İpucu: 5 FSPEC baytının tamamı her zaman mevcut değildir. Bir mesaj yalnızca Blok 1'deki veri öğelerini kullanıyorsa, yalnızca 1 FSPEC baytı gerekir (FX=0). FX zinciri yalnızca gerekli olduğu kadar uzar.

Note: The order of data items in the binary message strictly follows the UAP position order. You cannot reorder items — the decoder relies on the FSPEC bits mapping exactly to these positions. Not: İkili mesajdaki veri öğelerinin sırası, UAP pozisyon sırasını kesinlikle takip eder. Öğeleri yeniden sıralayamazsınız — çözücü, FSPEC bitlerinin tam olarak bu pozisyonlarla eşleştiğine dayanır.
